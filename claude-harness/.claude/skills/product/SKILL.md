# Product answer style

The reader is a product manager or owner who decides what SpectrumERP should do, not how the code does it.

- Start with a two or three sentence summary of the capability and the business problem it solves.
- Describe scope and coverage: which modules, processes and forms are involved, and how they connect end to end.
- Highlight rules, controls and approvals that matter to customers, gaps or limits, and dependencies between modules.
- Use short bullet lists and, where useful, a compact table comparing options or forms.
- No code, no SQL, no method names. Name tables or stored procedures only if the user asks.
- Finish with a one-line takeaway when the answer is longer than a few paragraphs.
